مثل 9router: مدل‌های رایگان
بدون هیچ کلیدی

پروایدر داخلی oc به دروازه‌ی Zen سایت OpenCode وصل می‌شود — همان کاری که 9router می‌کند. مدل‌های رایگانش فقط یک شناسه‌ی نشست می‌خواهند که OmniRouter خودش می‌سازد. هیچ ثبت‌نامی، هیچ کلیدی.

  • بدون کلید و ثبت‌نام — نصب کن و همان لحظه مدل‌های رایگان را صدا بزن
  • fetch خودکار مدل‌ها — لیست مدل‌ها زنده از منبع رسمی zen می‌آید و هر ۶۰ ثانیه تازه می‌شود.
  • استریم SSE و tool-calling — پاس‌ترو شفاف است و فرمت OpenAI دست‌نخورده می‌ماند.
  • پشتیبانی Anthropic — مسیر /v1/messages روی oc ترجمه‌ی کامل می‌شود؛ حتی بلوک‌های thinking.
  • مدل‌های پولی؟ کافی است OPENCODE_API_KEY را در env بگذاری؛ همان مسیر با کلید می‌رود: glm-5.3، claude، gpt.
  • سشن سفارشی — با هدر x-session-id خودت کنترلش کن.
NO KEY NEEDED# مدل‌های رایگان — بدون هیچ کلیدی curl http://localhost:8080/v1/chat/completions \ -H "Authorization: Bearer sk-omni" \ -H "Content-Type: application/json" \ -d '{ "model": "oc/big-pickle", "messages": [{"role":"user","content":"hi"}] }' # یا کدنویسی ایجنتی با مدل‌های free "model": "oc/nemotron-3-ultra-free" "model": "oc/mimo-v2.5-free" # مدل‌های پولی zen؟ فقط کلید بگذار: # OPENCODE_API_KEY=... → oc/glm-5.3 کار می‌کند

فهرست مدل‌های رایگان رایگانِ zen به‌مرور تغییر می‌کند — OmniRouter هر ۶۰ ثانیه خودش تازه می‌کند؛ هیچ هاردکدی در کار نیست.

RTK Token Saver

هر درخواست، ۲۰ تا ۴۰٪ ارزان‌تر

خروجی ابزارهایی مثل git diff و grep و ls و لاگ‌های طولانی، معمولاً ۳۰ تا ۵۰٪ بودجه‌ی پرامپت ایجنتی را می‌سوزانند. Token Saver داخلی OmniRouter — بر اساس ایده‌ی RTK در 9router — آن‌ها را قبل از رسیدن به مدل فشرده می‌کند: تشخیص خودکار، بدون تنظیمات و safe-by-design.

📄

git-diff

هانک‌ها حذف می‌شوند؛ فهرست فایل‌ها و آمار +/− برای هر فایل می‌ماند. یک دیف ۵۰هزار کاراکتری به چند صد بایت خلاصه می‌شود.

🔍

grep و لاگ‌ها

خطوط تکراری دی‌دوپ می‌شوند، سقف پاسخ برای هر فایل اعمال می‌شود و تکرارها به شکل ×N جمع می‌شوند؛ خروجی ده‌ها برابر کوچک‌تر می‌شود.

📁

find و ls و tree

فهرست‌های طولانی مسیرها به شمارش فایل و پوشه به‌علاوه‌ی نمونه‌ی مسیرهای اول فشرده می‌شوند؛ مدل تصویر درستی از ساختار می‌گیرد.

✂️

smart-truncate

متن عمومی بزرگ؟ سر و دم محتوای مهم نگه داشته می‌شود و بخش میانی با نشانگر حذف علامت‌گذاری می‌شود.

🛡️

امنیت تضمینی

اگر فیلتری خطا بدهد یا خروجی بزرگ‌تر شود، بی‌سروصدا متن اصلی می‌رود — خطای فشرده‌سازی هیچ‌وقت درخواست را نمی‌شکند.

🐴

Caveman و Ponytail

حالت‌های خروجی: پاسخ کوتاه و فنی با Caveman؛ کدنویسی YAGNI در سه سطح Lite و Full و Ultra با Ponytail. روی RTK سوار می‌شوند.

# دورزدن برای یک درخواستِ خاص (مثل 9router) X-Omni-Token-Saver: off # حالت خروجی لحظه‌ای X-Omni-Prompt-Mode: caveman # | ponytail-full | off # تنظیم کلی در داشبورد → Token Saver، یا env: RTK=on PROMPT_MODE=off
Custom Combos

زنجیره‌ی fallback
به نام خودت

مثل 9router، کمبوهای نام‌دار بساز: اشتراک گران → ارزان → رایگان. هر گام که شکست یا سهمیه‌اش تمام شد، بعدی همین‌طور بی‌سروصدا جواب می‌دهد. مدل‌های auto هم خودشان همین زنجیره‌ی هوشمند را دارند.

  • تعریف از داشبورد یا مستقیم از env با COMBOS
  • مصرف مثل یک مدل معمولی: "model": "combo:my-stack"
  • کمبوی آماده‌ی free-stack در نصب تازه: qwen → gemini → OpenCode free
  • اجتماع با سهمیه‌ی کلید و allowlist هر مدل
# داشبورد → کمبوها → «free-stack» 1. qwen/qwen3.8-max # قوی‌ترین برای ایجنت 2. gemini/gemini-3.6-flash # مهمان، بی‌توکن 3. oc/big-pickle # رایگان، بی‌کلید # بعد در هر کلاینتی: { "model": "combo:free-stack" } # نتیجه: کدنویسی که هیچ‌وقت نمی‌ایستد — $0
Everything Included

Failover بین پروایدرها

خطای ۴۲۹ یا ۴۰۱ یا ۵xx؟ کاندیدای بعدی قبل از اولین بایت استریم وارد می‌شود. پروایدرِ تازه‌خطاکار کوتاه به نیمکت می‌نشیند (cooldown) تا ترجیح سلامت حفظ شود.

آمار و لاگ زنده

توکن واقعی هر درخواست (استخراج usage از JSON و دم SSE)، باکت ساعتی ۴۸گانه، per-provider/model/key، لاگ حلقه‌ای ۵۰۰تایی.

کلیدهای sk- با سهمیه‌ی درخواست، allowlist مدل (qwen/*) و مدیریت کامل از داشبورد — توکن‌های وب هیچ‌وقت به کلاینت نمی‌رسند.

Quick Start

سه قدم تا اولین پاسخ

بدون Node، بدون Python، بدون Docker. باینری را بگیر، اجرا کن، از داشبورد کلید بگیر — تمام.

دانلود و اجرا

از Releases بگیر یا بساز:

git clone https://github.com/Godde3s/omnirouter cd omnirouter && go build -o omnirouter . ./omnirouter # یا start.bat در ویندوز

داشبورد و کلید

localhost:8080 را باز کن (رمز: ADMIN_PASSWORD). کلید sk- آماده است؛ توکن‌های وب را در .env بگذار.

# .env — همه اختیاری QWEN_TOKEN=… DEEPSEEK_TOKENS=… GEMINI_COOKIES=… # خالی = مهمان OPENCODE_API_KEY=… # فقط برای مدل‌های پولی zen

به هر کلاینتی وصل کن

Endpoint را بده، مدل بگو — یا auto بگذار:

Base URL: http://localhost:8080/v1 API Key: sk-… (از داشبورد) Model: auto # یا combo:free-stack
Bring Your Own Agent

اتصال همه‌ی کلاینت‌ها

هر ابزاری که OpenAI یا Anthropic حرف می‌زند، با OmniRouter حرف می‌زند. اسنیپت را کپی کن، endpoint و کلید را بگذار، تمام.

در ~/.config/opencode/opencode.json — مدل‌های oc/* هیچ کلید بیرونی نمی‌خواهند:

{ "provider": { "omni": { "npm": "@ai-sdk/openai-compatible", "name": "OmniRouter", "options": { "baseURL": "http://localhost:8080/v1", "apiKey": "sk-omni" }, "models": { "oc/big-pickle": {}, "qwen/qwen3.8-max": {}, "auto": {} } } } }

تنظیمات Cline → API Provider:

Provider: OpenAI Compatible Base URL: http://localhost:8080/v1 API Key: sk-omni (از داشبورد) Model: qwen/qwen3.8-max # یا combo:free-stack

برای حالت Anthropic در Cline، همان Base URL با /v1/messages و کلید sk- کار می‌کند.

Claude Code با پروتکل Anthropic وصل می‌شود:

export ANTHROPIC_BASE_URL=http://localhost:8080 export ANTHROPIC_API_KEY=sk-omni export ANTHROPIC_MODEL=qwen/qwen3.8-max claude "سلام!"

در ~/.codex/config.toml:

[model_providers.omni] name = "OmniRouter" base_url = "http://localhost:8080/v1" env_key = "OMNI_API_KEY" model = "auto" model_provider = "omni"

Cursor Settings → Models → OpenAI API Key → Override Base URL:

Base URL: http://localhost:8080/v1 API Key: sk-omni Model: oc/big-pickle # یا هر مدل کاتالوگ

Hermes با فرمت OpenAI و tool-calling کامل (تست‌شده زنده با R1→R2):

endpoint: http://localhost:8080/v1 api_key: sk-omni model: qwen/qwen3.8-max tools: true # فراخوانی ابزار اثبات‌شده

FAQ

سؤال‌های پرتکرار

واقعاً بدون هیچ کلیدی می‌شود کدنویسی کرد؟
بله — دو مسیر بدون کلید داریم: Gemini مهمان (برای بریج gemini هیچ کوکی‌ای لازم نیست؛ در تست‌های ما از IP دیتاسنتر هم جواب داد) و مدل‌های رایگان OpenCode Zen از طریق پروایدر oc که فقط یک شناسه‌ی نشست تصادفی می‌خواهد که روتر خودش می‌سازد. کمبوی آماده‌ی combo:free-stack همین‌ها را پشت هم می‌چیند.
سهمیه‌ی رایگان zen تمام می‌شود چه؟
اگر در زنجیره‌ی auto یا کمبو، بعد از oc/* یک گام دیگر باشد، روتر خودش می‌رود بعدی. خطای FreeUsageLimitError مثل هر ۴۲۹ دیگری retryable است و failover را فعال می‌کند. برای سهمیه‌ی بیشتر zen می‌توانی OPENCODE_API_KEY بگذاری تا مدل‌های پولی (مثل oc/glm-5.3) هم باز شوند.
RTK چطور مطمئن می‌شود چیزی مهم از دست نمی‌رود؟
فیلترها ساختار محتوای ابزار را می‌شناسند: دیف، وضعیت گیت، grep و فهرست مسیرها. فقط بخش‌های تکراری و حجمی خلاصه می‌شوند — آمار مثبت و منفی، مسیرها و خطوط یکتا سر جایشان می‌مانند. اگر فیلتر مطمئن نباشد یا خروجی بزرگ‌تر از ورودی شود، متن اصلی دست‌نخورده می‌رود. با هدر X-Omni-Token-Saver: off هم برای هر درخواست می‌توانی کلاً خاموشش کنی.
توکن‌های وبم کجا می‌روند؟ امن است؟
توکن‌ها فقط در .env یا استور محلی خودت می‌مانند و بین روتر و سایت ارائه‌دهنده رد و بدل می‌شوند. کلاینت‌ها فقط کلیدهای sk- مجازیِ خود روتر را می‌بینند. هیچ چیزی به هیچ سروری غیر از خود ارائه‌دهنده‌ها ارسال نمی‌شود — همه‌چیز تک‌باینری محلی است.
فرق OmniRouter با گذاشتن مستقیم بریج‌ها کنار هم؟
بریج‌های تکی هرکدام یک پورت، یک فرمت و یک توکن دارند. OmniRouter همه را پشت یک endpoint استاندارد می‌گذارد: یک کلید برای همه، resolve خودکار مدل، failover بین سرویس‌ها، سهمیه و آمار یکپارچه، و Token Saver که روی همه اعمال می‌شود — چیزی که با N بریج مجزا عملاً ممکن نیست.
روی ویندوز چطور اجرا کنم؟
از Releases پکیج windows-amd64.zip را بگیر، extract کن و start.bat را بزن — اولین اجرا .env می‌سازد و راهنما نشان می‌دهد. باینری‌های macOS (اینتل/ARM) و لینوکس (amd64/ARM64) هم در همان ریلیز هستند.

Features

هرچیزی که از یک API واقعی انتظار داری

نه پروکسی خام، نه اسکرپ شکننده — یک لایه‌ی روتر کامل روی چهار بریج مهندسی‌شده.

🔌

یک درگاه، دو پروتکل کامل

/v1/chat/completions سازگار با OpenAI و /v1/messages سازگار با Anthropic — همراه /v1/messages/count_tokens و /v1/models زنده. استریم SSE واقعاً افزایشی است (نه re-parse کل بافر) و بلوک‌های thinking هم می‌آیند.

🛠️

Tool Calling برای ایجنت‌ها

چرخه‌ی کامل R1→R2 برای Hermes، OpenCode و Cline: تعریف ابزار → فراخوانی tool_calls با JSON معتبر → نتیجه → پاسخ نهایی. روی هر چهار بریج، با اثبات زنده.

🚦

Failover خودکار

مدل auto روی زنجیره‌ی قابل‌تنظیم می‌چرخد؛ خطای 401/403/429/5xx قبل از اولین بایت استریم → پروایدر بعدی.

📊

آمار مصرف واقعی

توکن ورودی/خروجی واقعی هر درخواست، نمودار ۴۸ ساعته، تفکیک per-provider / per-model / per-key.

🎭

Alias مدل‌ها

gpt-4o را به qwen3.8-max وصل کن؛ کلاینت‌های یک‌دست، بی‌دردسر روی وبِ رایگان.

۳۰ ثانیه تا اولین پاسخ

باینری آماده را از Releases بگیر، اجرا کن، کلید را از داشبورد بردار — تمام.

۱

دانلود و اجرا

از صفحه‌ی Releases آخرین بسته‌ی پلتفرم خودت را بردار و اجرا کن. اسکریپت start، اولین بار .env را هم می‌سازد.

# Linux / macOS tar xzf omnirouter-linux-amd64.tar.gz ./start.sh # Windows — start.bat را اجرا کن # Docker — docker compose up -d
۲

اعتبار بگذار (اختیاری!)

Gemini و GLM و Qwen مهمان کار می‌کنند. برای سهمیه‌ی کامل: توکن‌ها را در .env بگذار یا از ابزارهای لاگین استفاده کن.

# .env — همه اختیاری به‌جز DeepSeek QWEN_TOKENS=token1,token2 GEMINI_COOKIES=__Secure-1PSID=… DEEPSEEK_TOKENS=… # ./ds-login
۳

کلید بگیر، وصل شو

داشبورد را باز کن، کلید sk- را بردار و در هر کلاینتی بگذار. مدلِ auto خودش بهترین مسیر را انتخاب می‌کند.

curl http://localhost:8080/v1/chat/completions \ -H "Authorization: Bearer sk-omni-…" \ -d '{"model":"auto","messages":[…]}'

OpenCode، Cline، Claude Code، Hermes…

هر کلاینتی که OpenAI یا Anthropic حرف می‌زند، یک‌جا به همه‌ی مدل‌ها وصل می‌شود — با Tool Calling کامل.

OpenCode

فایل opencode.json پروژه را بساز و پروایدر را معرفی کن. مدل auto یا هر مدلی از /v1/models.

  • پروتکل openai-compatible — استریم و ابزارها پشتیبانی می‌شوند
  • برای حالت Anthropic، baseURL را روی ریشه بگذار و /v1/messages استفاده می‌شود
  • کلید را از داشبورد بگیر: sk-omni-…
{ "$schema": "https://opencode.ai/config.json", "provider": { "omnirouter": { "npm": "@ai-sdk/openai-compatible", "options": { "baseURL": "http://localhost:8080/v1", "apiKey": "sk-omni-…" }, "models": { "auto": {}, "qwen/qwen3.8-max": {}, "gemini/gemini-3.6-flash": {} } } } }

Cline (VS Code)

در تنظیمات Cline یکی از دو حالت را انتخاب کن — هر دو کامل تست شده‌اند:

  • API Provider: OpenAI Compatible — Base URL: http://localhost:8080/v1
  • یا Provider: Anthropic — خودش /v1/messages می‌زند
  • Model ID: auto برای failover خودکار
# OpenAI Compatible Base URL: http://localhost:8080/v1 API Key: sk-omni-… Model ID: auto # Anthropic Compatible Base URL: http://localhost:8080 API Key: sk-omni-… Model ID: qwen/qwen3.8-max

Claude Code

با دو متغیر محیطی، کل Claude Code روی وبِ رایگان می‌چرخد — بلوک‌های thinking هم واقعی پاس می‌شوند.

  • ANTHROPIC_BASE_URL به ریشه‌ی روتر اشاره می‌کند (بدون /v1)
  • ANTHROPIC_AUTH_TOKEN = کلید sk- داشبورد
  • /v1/messages/count_tokens هم پاسخ می‌دهد
export ANTHROPIC_BASE_URL=http://localhost:8080 export ANTHROPIC_AUTH_TOKEN=sk-omni-… # سپس عادی اجرا کن: claude "این ریپو رو بررسی کن و تست بنویس"

Hermes Agent

Hermes چرخه‌ی کامل tool-calling می‌زند؛ روتر هم R1→R2 را در تمام بریج‌ها پاس می‌دهد (اثبات زنده با get_weather).

  • OpenAI base: http://localhost:8080/v1 + کلید sk-
  • برای reasoning مدل‌ها، بلوک thinking در Anthropic جدا می‌آید
  • AGENT_MODE=1 در .env فعال بماند
export OPENAI_BASE_URL=http://localhost:8080/v1 export OPENAI_API_KEY=sk-omni-… export MODEL=qwen/qwen3.8-max

هر کلاینت دیگری

هر نرم‌افزاری که «OpenAI-compatible» یا «Anthropic-compatible» دارد — از Dify و LobeChat تا اسکریپت‌های خودت.

  • Base URL: http://localhost:8080/v1 (OpenAI) یا ریشه (Anthropic)
  • کلید از داشبورد — چند کلید با سهمیه‌ی جدا بساز
  • مدل‌های زنده: GET /v1/models
# کشف زنده‌ی مدل‌ها curl http://localhost:8080/v1/models -H "Authorization: Bearer sk-omni-…" # شمارش توکن (Anthropic parity) curl http://localhost:8080/v1/messages/count_tokens \ -d '{"model":"auto","messages":[…]}'

FAQ

سوالات پرتکرار

بله. روتر به جای کلیدهای رسمی، از نسخه‌ی وبِ رایگان چت‌بات‌ها (chat.qwen.ai، chat.z.ai، chat.deepseek.com، gemini.google.com) استفاده می‌کند و آن‌ها را به API استاندارد تبدیل می‌کند. کیفیت پاسخ همان مدل وب است — با پروتکل کامل API: استریم، ابزارها، آمار.

Gemini مهمان از IP دیتاسنتر هم پاسخ داد (اثبات زنده در توسعه). Qwen مهمان روی IPهای دیتاسنتر محدود است — ابزار qwen-bx یک جلسه‌ی تمیز از مرورگر headless می‌گیرد. DeepSeek همیشه نیاز به توکن اکانت دارد (ds-login).

۹router روی APIهای رسمی/OAuth تمرکز دارد؛ OmniRouter همان تجربه‌ی روتر (کلید، آمار، alias، failover، داشبورد) را اما روی وبِ رایگان مدل‌ها می‌آورد و هر API دلخواه را هم کنارشان می‌پذیرد. تک‌باینری است، نیازی به دیتابیس و Node ندارد و داشبورد فارسی دارد.

نه. کاتالوگ مدل‌ها با TTL کوتاه از خود سرویس‌ها کشف زنده می‌شود؛ اگر سرویس مدل جدیدی اضافه کند، روتر خودش می‌بیند. نام‌های نمایشی alias هم می‌پذیرند.

کلاینت‌ها فقط با کلیدهای sk- داشبورد وارد می‌شوند؛ هر کلید سهمیه و لیست مدل مجاز دارد. بین هسته‌ی روتر و بریج‌ها توکن داخلی (AUTH_TOKEN) رد و بدل می‌شود و داشبورد با رمز ADMIN_PASSWORD محافظت می‌شود. همه‌چیز لوکال اجرا می‌شود.

از بخش Quick Start همین صفحه — سه مرحله: دانلود بسته‌ی پلتفرم، اجرای start.sh / start.bat (یا داکر)، برداشتن کلید از داشبورد روی پورت 8080.

این پروژه آموزشی است و رابط کاربری وب سرویس‌ها را طبق رفتار عمومی آن‌ها استفاده می‌کند؛ مسئولیت رعایت شرایط سرویس‌ها با کاربر است. برای کار تجاری، APIهای رسمی را به‌عنوان پروایدر سفارشی اضافه کنید.

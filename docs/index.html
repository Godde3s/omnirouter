OpenCode Free · No API Key

مثل 9router: مدل‌های رایگان،
بدون هیچ کلیدی

پروایدر داخلی oc به دروازه‌ی Zen سایت OpenCode وصل می‌شود — همان کاری که 9router می‌کند. مدل‌های رایگانش فقط یک شناسه‌ی نشست می‌خواهند که OmniRouter خودش می‌سازد. هیچ ثبت‌نامی، هیچ کلیدی.

  • بدون کلید و ثبت‌نام — نصب کن و همان لحظه مدل‌های رایگان را صدا بزن.
  • فهرست مدل زنده — مدل‌ها هر ۶۰ ثانیه از منبع رسمی zen تازه می‌شوند؛ هیچ هاردکدی در کار نیست.
  • استریم SSE و tool-calling — پاس‌ترو شفاف است و فرمت OpenAI دست‌نخورده می‌ماند.
  • پشتیبانی Anthropic — مسیر /v1/messages روی oc ترجمه‌ی کامل می‌شود؛ حتی بلوک‌های thinking.
  • مدل‌های پولی zen؟ فقط OPENCODE_API_KEY را در env بگذار؛ همان مسیر با کلید باز می‌شود: glm-5.3، claude، gpt.
  • سشن سفارشی — با هدر x-session-id خودت کنترلش کن.
NO KEY NEEDED# free zen models — zero keys curl http://localhost:8080/v1/chat/completions \ -H "Authorization: Bearer sk-omni" \ -H "Content-Type: application/json" \ -d '{ "model": "oc/big-pickle", "messages": [{"role":"user","content":"hi"}] }' # more free ids for agentic coding "model": "oc/nemotron-3-ultra-free" "model": "oc/mimo-v2.5-free" # paid zen? just add a key: # OPENCODE_API_KEY=... -> oc/glm-5.3

شناسه‌های رایگان zen به‌مرور تغییر می‌کنند — OmniRouter هر ۶۰ ثانیه خودش لیست را تازه می‌کند و هرچه بیاید، همان لحظه در کاتالوگ و داشبورد می‌بینی.

RTK Token Saver

هر درخواست، ۲۰ تا ۴۰٪ ارزان‌تر

خروجی ابزارهایی مثل git diff و grep و لاگ‌های طولانی معمولاً ۳۰ تا ۵۰٪ بودجه‌ی پرامپت ایجنتی را می‌سوزانند. Token Saver داخلی OmniRouter — بر اساس ایده‌ی RTK در 9router — آن‌ها را قبل از رسیدن به مدل فشرده می‌کند: تشخیص خودکار، بدون تنظیمات و safe-by-design.

git-diff

هانک‌های حجیم حذف می‌شوند؛ فهرست فایل‌ها و آمار +/− برای هر فایل می‌ماند. یک دیف ۵۰هزار کاراکتری به چند صد بایت خلاصه می‌شود.

grep و لاگ‌ها

خطوط تکراری دی‌دوپ می‌شوند، سقف پاسخ برای هر فایل اعمال می‌شود و تکرارها به شکل ×N جمع می‌شوند؛ خروجی ده‌ها برابر کوچک‌تر می‌شود.

find و ls و tree

فهرست‌های طولانی مسیرها به شمارش فایل و پوشه به‌علاوه‌ی نمونه‌ی مسیرهای اول فشرده می‌شوند؛ مدل تصویر درستی از ساختار پروژه می‌گیرد.

smart-truncate

متن عمومی بزرگ؟ سر و دمِ محتوای مهم نگه داشته می‌شود و بخش میانی با نشانگر حذف علامت‌گذاری می‌شود.

امنیت تضمینی

اگر فیلتری خطا بدهد یا خروجی بزرگ‌تر شود، بی‌سروصدا متن اصلی می‌رود — خطای فشرده‌سازی هیچ‌وقت درخواست را نمی‌شکند.

Caveman و Ponytail

حالت‌های خروجی: پاسخ کوتاه و فنی با Caveman؛ کدنویسی YAGNI در سه سطح Lite و Full و Ultra با Ponytail — روی RTK سوارند.

# bypass for one single request (like 9router) X-Omni-Token-Saver: off # output mode on the fly X-Omni-Prompt-Mode: caveman # | ponytail-full | off # global default — dashboard or env RTK=on PROMPT_MODE=off

Everything Included

هر چیزی که از یک روتر انتظار داری

همه‌ی قابلیت‌های 9router که روی معماری بریج-وب معنا دارند — به‌علاوه‌ی چیزهایی که فقط OmniRouter دارد: PoW واقعی دیپ‌سیک، کشف زنده‌ی مدل گوگل و تشخیص خودکار ابزار.

Failover بین پروایدرها

خطای ۴۲۹ یا ۴۰۱ یا 5xx؟ کاندیدای بعدی قبل از اولین بایت استریم وارد می‌شود و پروایدر خطاکار کوتاه به نیمکت می‌نشیند تا ترجیح سلامت حفظ بماند.

دو پروتکل، یک روتر

/v1/chat/completions و /v1/messages — ترجمه‌ی کامل OpenAI و Anthropic با بلوک‌های thinking و tool-calling در هر دو سو.

آمار و لاگ زنده

توکن واقعی هر درخواست (استخراج usage از JSON و دم SSE)، باکت ساعتی ۴۸گانه به تفکیک پروایدر و مدل و کلید، لاگ حلقه‌ای ۵۰۰تایی.

کلیدهای مجازی

کلیدهای sk- با سهمیه‌ی درخواست، allowlist مدل مثل qwen/* و مدیریت کامل از داشبورد — توکن‌های وب هیچ‌وقت به کلاینت نمی‌رسند.

Alias مدل

هر نامی به هر مدل آپستریم. "glm" را به glm-5.3 مپ کن؛ کلاینت‌ها بی‌تغییر می‌مانند و جابه‌جایی مدل یک کلیک است.

پروایدر سفارشی

هر API سازگار OpenAI را وصل کن: از Gemini AI Studio و OpenRouter و Groq گرفته تا Ollama و LM Studio — با پری‌ست آماده و fetch خودکار مدل‌ها.

count_tokens محلی

/v1/messages/count_tokens بدون رفت‌وبرگشت به آپستریم جواب می‌دهد — برای بودجه‌بندی کانتکست کلاینت‌ها.

داشبورد فارسی ۲.۰

نمای کلی با نمودار ۴۸ساعته، پروایدرها، Token Saver، کمبوها، کلیدها، پلی‌گراند استریم با نمایش thinking و لاگ زنده — همه RTL.

یک فایل، هرجا

تک‌باینری Go بدون وابستگی برای ویندوز، لینوکس و مک (amd64 + arm64)، اسکریپت‌های start.sh و start.bat و docker-compose آماده.

Quick Start

سه قدم تا اولین پاسخ

بدون Node، بدون Python، بدون Docker. باینری را بگیر، اجرا کن، از داشبورد کلید بگیر — تمام.

دانلود و اجرا

از Releases بگیر یا خودت بساز:

git clone https://github.com/Godde3s/omnirouter cd omnirouter && go build -o omnirouter . ./omnirouter # or start.bat on windows

داشبورد و کلید

localhost:8080 را باز کن (رمز: ADMIN_PASSWORD). کلید sk- آماده است؛ توکن‌های وب را در .env بگذار.

# .env -- all optional QWEN_TOKEN=... DEEPSEEK_TOKENS=... GEMINI_COOKIES=... # empty = guest OPENCODE_API_KEY=... # paid zen only

به هر کلاینتی وصل کن

Endpoint را بده، مدل بگو — یا auto بگذار:

Base URL: http://localhost:8080/v1 API Key: sk-... # from dashboard Model: auto # or combo:free-stack
Bring Your Own Agent

اتصال همه‌ی کلاینت‌ها

هر ابزاری که OpenAI یا Anthropic حرف می‌زند، با OmniRouter حرف می‌زند. اسنیپت را کپی کن، endpoint و کلید را بگذار، تمام.

در ~/.config/opencode/opencode.json — مدل‌های oc/* هیچ کلید بیرونی نمی‌خواهند:

{ "provider": { "omni": { "npm": "@ai-sdk/openai-compatible", "name": "OmniRouter", "options": { "baseURL": "http://localhost:8080/v1", "apiKey": "sk-omni" }, "models": { "oc/big-pickle": {}, "qwen/qwen3.8-max": {}, "auto": {} } } } }

تنظیمات Cline ← API Provider:

Provider: OpenAI Compatible Base URL: http://localhost:8080/v1 API Key: sk-omni # from dashboard Model: qwen/qwen3.8-max # or combo:free-stack

برای حالت Anthropic در Cline، همان Base URL با مسیر /v1/messages و کلید sk- کار می‌کند.

Claude Code با پروتکل Anthropic وصل می‌شود:

export ANTHROPIC_BASE_URL=http://localhost:8080 export ANTHROPIC_API_KEY=sk-omni export ANTHROPIC_MODEL=qwen/qwen3.8-max claude "hello!"

در ~/.codex/config.toml:

model_providers.omni] name = "OmniRouter" base_url = "http://localhost:8080/v1" env_key = "OMNI_API_KEY" model = "auto" model_provider = "omni"

Cursor ← Settings ← Models ← OpenAI API Key ← Override Base URL:

Base URL: http://localhost:8080/v1 API Key: sk-omni Model: oc/big-pickle # or any catalog id

Hermes با فرمت OpenAI و tool-calling کامل — تست‌شده‌ی زنده با چرخه‌ی R1 به R2:

endpoint: http://localhost:8080/v1 api_key: sk-omni model: qwen/qwen3.8-max tools: true # proven live
OAuth Device Flow · RFC 8628

اتصال با یک کلیک، بدون کپی کلید

مثل 9router: ابزارت را بگو کی هستی، تو فقط یک کد را تأیید کن. برای هر کلاینت یک کلید مجازی جدا ساخته می‌شود که هر لحظه از داشبورد قابل لغو است.

۱ابزارت کد می‌گیرد. یک درخواست ساده به POST /oauth/device/start با نام کلاینت — کد ۸ کاراکتری مثل K7QW-2XRT برمی‌گردد، همان استانداردی که Copilot و Cline استفاده می‌کنند.
۲تو تأیید می‌کنی. صفحه‌ی فارسی /oauth/authorize را باز کن، کلاینت و کد را ببین و دکمه‌ی «تأیید و اتصال» را بزن. از داشبورد هم می‌شود تأیید یا رد کرد.
۳کلید خودکار ساخته می‌شود. ابزار با POST /oauth/device/poll کلید مجازی اختصاصی sk-omni-… را می‌گیرد؛ آمار مصرفش جدا نگه‌داری می‌شود و لغو آن لحظه‌ای است.

صفحه‌ی تأیید فارسی — همان لحظه در مرورگر

کد را که باز کنی، OmniRouter نشان می‌دهد چه کلاینتی، چه دسترسی‌ای خواسته. کلید ساخته‌شده فقط برای همان ابزار است: می‌توانی سقف درخواست بگذاری، مدل‌هایش را محدود کنی یا با یک دکمه از پنل «اتصالات» داشبورد لغوش کنی — دقیقاً حس داشبورد 9router، با پالت و زبان خودمان.

امنیت محلی: تأیید فقط از localhost یا با نشست ادمین پذیرفته می‌شود؛ کدها ۱۵ دقیقه‌ای منقضی می‌شوند و هر بار مصرف، بی‌اعتبار می‌گردند.
CONSENT$ curl -s -X POST localhost:8080/oauth/device/start \ -d '{"client":"cline"}' { "user_code": "K7QW-2XRT", "verification_uri": "http://localhost:8080/oauth/authorize", "expires_in": 900 } # بعد از تأیید در مرورگر: $ curl -s -X POST localhost:8080/oauth/device/poll \ -d '{"device_code":"omni_…"}' { "access_token": "sk-omni-…", "token_type": "bearer" }

سؤال‌های پرتکرار

واقعاً بدون هیچ کلیدی می‌شود کدنویسی کرد؟
بله — دو مسیر بدون کلید داریم. اول Gemini مهمان: برای بریج gemini هیچ کوکی‌ای لازم نیست و در تست‌های ما از IP دیتاسنتر هم جواب داد. دوم مدل‌های رایگان OpenCode Zen از طریق پروایدر oc که فقط یک شناسه‌ی نشست تصادفی می‌خواهد که روتر خودش می‌سازد. کمبوی آماده‌ی combo:free-stack همین‌ها را پشت هم می‌چیند.
چطور Cline یا Kilo Code را بدون کپی‌پیست کلید وصل کنم؟
با OAuth Device Flow جدید v1.3.0. در ابزار یا ترمینال یک بار POST /oauth/device/start را با نام کلاینت صدا بزن؛ کد ۸ کاراکتری می‌گیری. آن را در صفحه‌ی /oauth/authorize تأیید کن — تمام. ابزار با poll کلید مجازی خودش را خودکار می‌گیرد و از آن لحظه در پنل «اتصالات» داشبورد با آمار مستقل می‌بینی‌اش. این دقیقاً همان تجربه‌ی اتصال Copilot و Cline در 9router است.
سهمیه‌ی رایگان zen تمام می‌شود چه؟
اگر در زنجیره‌ی auto یا کمبو، بعد از oc/* یک گام دیگر باشد، روتر خودش می‌رود سراغ بعدی. خطای FreeUsageLimitError مثل هر ۴۲۹ دیگری قابل retry است و failover را فعال می‌کند. برای سهمیه‌ی بیشتر هم می‌توانی OPENCODE_API_KEY بگذاری تا مدل‌های پولی مثل oc/glm-5.3 باز شوند.
RTK چطور مطمئن می‌شود چیزی مهم از دست نمی‌رود؟
فیلترها ساختار محتوای ابزار را می‌شناسند: دیف، وضعیت گیت، grep و فهرست مسیرها. فقط بخش‌های تکراری و حجیم خلاصه می‌شوند — آمار مثبت و منفی، مسیرها و خطوط یکتا سر جایشان می‌مانند. اگر فیلتر مطمئن نباشد یا خروجی بزرگ‌تر از ورودی شود، متن اصلی دست‌نخورده می‌رود. با هدر X-Omni-Token-Saver: off هم برای هر درخواست می‌توانی کلاً خاموشش کنی.
توکن‌های وبم کجا می‌روند؟ امن است؟
توکن‌ها فقط در .env یا استور محلی خودت می‌مانند و بین روتر و سایت ارائه‌دهنده رد و بدل می‌شوند. کلاینت‌ها فقط کلیدهای مجازی sk- خود روتر را می‌بینند. هیچ چیزی به هیچ سروری غیر از خود ارائه‌دهنده‌ها ارسال نمی‌شود — همه‌چیز تک‌باینری محلی است.
فرق OmniRouter با گذاشتن بریج‌ها کنار هم چیست؟
بریج‌های تکی هرکدام یک پورت، یک فرمت و یک توکن دارند. OmniRouter همه را پشت یک endpoint استاندارد می‌گذارد: یک کلید برای همه، resolve خودکار مدل، failover بین سرویس‌ها، سهمیه و آمار یکپارچه، و Token Saver که روی همه اعمال می‌شود — چیزی که با چند بریج مجزا عملاً ممکن نیست.
روی ویندوز چطور اجرا کنم؟
از Releases پکیج windows-amd64.zip را بگیر، extract کن و start.bat را اجرا کن — اولین اجرا فایل .env می‌سازد و راهنما نشان می‌دهد. باینری‌های macOS (اینتل و ARM) و لینوکس (amd64 و ARM64) هم در همان ریلیز هستند.
